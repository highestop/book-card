# BookCard

专注读书笔记的原生 macOS 应用。把微信读书的每条划线、想法做成一张书签，按书籍与章节收藏。支持 macOS 14+、iOS 17+ 和 iPadOS 17+，Swift 6 工具链，无第三方应用依赖。

- **最近书签**：启动先展示缓存中最近标记的笔记，后台同步；可逐张翻阅、回到最新，或打开这本书。卡片以章节／文章标题为一级标题、书名／公众号名为二级标题，展示有效引用、想法与标记时间，支持选择文字和复制完整来源。
- **全部书签**：统一使用卡片瀑布流，按实际高度填入最短列；窗口缩放和长笔记展开后重新排列。支持跨书搜索书名、作者、文章、引用及想法，不再提供视图切换及来源、笔记类型筛选。
- **书内浏览**：每个公众号是一本书，每篇文章是一个章节。章节目录支持筛选，卡片可展开全文，公众号文章可打开原文。
- **纸质风格**：暖白纸张、书签丝带、卡片叠放及翻卡过渡；遵循系统「减少动态效果」设置。

共享核心位于 `Sources/BookCardCore/`，只维护一套数据模型、同步、搜索和 SwiftData 存储；独立 UI 分别位于 `Apps/macOS/`、`Apps/Mobile/iPhone/`、`Apps/Mobile/iPad/`。移动端组件位于 `Apps/Mobile/Components/`，各端共用的瀑布流布局位于 `Apps/Shared/`。iPhone 使用底部导航，iPad 使用可折叠侧栏，全部使用同一笔记缓存与同步逻辑。

## 使用和构建

```sh
./scripts/build-app.sh
open build/BookCard.app
./scripts/test.sh
./scripts/preview.sh
./scripts/run-ios.sh iphone
./scripts/run-ios.sh ipad
./scripts/build-ios.sh simulator
```

首次使用，在应用内打开微信读书官方 Key 页面，登录生成 Key，粘贴后连接。进度、阅读时长等功能已移除，旧版笔记缓存可继续使用。设置中可立即同步、完整校验、更换或移除 Key、清除本地缓存。也可用 `⌘R` 同步。

需要完整 Xcode（SwiftData 宏及移动端 SDK）；脚本优先使用 `/Applications/Xcode.app`，也支持通过 `DEVELOPER_DIR` 指定，且不会修改系统 `xcode-select`。脚本生成本机临时签名应用，未做发布签名或公证；重新编译后钥匙串可能要求重新授权。`preview.sh` 使用合成数据生成实际 SwiftUI 页面预览到 `build/previews/`，不读取账号数据或钥匙串。

## 缓存与同步

- 每次启动自动同步；应用重新回到前台且距离上次尝试超过 5 分钟时再检查。缓存立即可读，不等待网络。
- 遍历全部笔记本分页，以最近笔记时间及划线、想法数量比较每本书的成功同步记录，仅重新获取新增或变化的书。失败来源保留缓存及旧版本标记，下次自动重试。
- 官方正文接口没有增量游标；想法的 `synckey` 仅用于分页。因此增量粒度是书籍，不是单条笔记。未变化的书每隔 24 小时完整校验一次，以发现数量及最近时间未改变的编辑；设置中也可主动完整校验。
- 每本书通过身份、数量及分页检查后，以 SwiftData 事务单独保存该来源及同步状态。数量明确的完整响应会反映服务端删除；数量不明且历史笔记缺失时保留旧缓存。已不在服务端列表的书保留作离线档案。
- 公众号文章按 ID 分组；优先采用笔记响应中的有效标题，空字符串继续尝试章节名。缺少章节时按 UID 查询官方 `/book/chapterinfo`；缺少文章标题时查询 `/review/single` 的文章信息，再用独立、无 Key 的会话读取公开页面的 `og:title` 或文章标题节点。接口返回范围取决于服务端，无法解析时保留笔记，显示「文章（标题暂缺）」。
- 公众号笔记先保存正文，再以最多 4 个并发请求补全标题。未变化的缓存中如仍有缺失标题，下次同步只重试标题补全；已解析标题复用缓存，重试不延后正文的每日完整校验。图片占位及媒体标签不作为引用显示，混合内容保留可读文字；纯图片笔记保留来源与时间提示，不丢弃记录。时间缺失时明确显示「标记时间未提供」。

## 数据与隐私

- Key 仅保存到 macOS 钥匙串，不进入缓存、日志或仓库。每个 Key 使用独立缓存，移除 Key 后仍可离线阅读。
- 原生 URLSession 直接访问官方 HTTPS 网关，禁用重定向，不经开发者服务器。参数平铺，`skill_version` 为 `1.0.5`。
- macOS 数据位于 `~/Library/Application Support/BookCard/`，移动端位于各自应用沙箱。每个 Key 使用独立 SwiftData 数据库，目录权限 0700、文件权限 0600；未额外加密，可能进入系统备份。CloudKit 同步关闭，各设备独立同步。
- 保留原有 JSON → SwiftData 迁移；V1 数据库轻量迁移到 V2，只增加每本书的同步状态记录。旧阅读进度字段仅为存储兼容保留，不再请求或展示；迁移失败保留原始数据，缓存无法读取时停止写入。
- 清除本地数据会删除本应用所有 Key 对应的缓存，不修改微信读书中的任何内容。接口仅用于读取。
- 应用内「书签」指划线与想法的卡片展示；微信读书的阅读位置书签目前不能通过官方接口导出，不纳入卡片数量。

自动化测试覆盖 SwiftData V1 → V2 迁移、事务回滚、同步状态持久化、分页、错误响应、缓存迁移、Key 隔离、增量跳过与重试、完整校验、删除与离线保护、媒体展示及公众号分组。真实账号的 Key 生命周期和服务端数据形态仍需在应用中实测。

接口依据：[官方章节文档](https://github.com/Tencent/WeChatReading/blob/main/skills/book.md)、[微信读书官方笔记文档](https://github.com/Tencent/WeChatReading/blob/main/skills/notes.md)。交互参考：[Readwise 的笔记回顾](https://readwise.io/read)。
