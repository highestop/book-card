# BookCard macOS MVP

本地优先的微信读书阅读进度与笔记浏览器。macOS 14 或更新版本，Swift 6 工具链，无第三方依赖。

## 使用

双击 `build/BookCard.app`。第一次启动，点击官方 Key 页面，在微信读书登录后生成 Key，粘贴到应用并点击「连接并读取数据」。主界面分为两个 Tab：

- **我读过的书**：遍历当前书架和笔记本中的书籍进度，展示所有扫描到的书籍（包括未读、在读、已读完），默认按进度降序；可选择进度升序、最近阅读、阅读时长、书名排序，选择会保存在本机。进度未获取的书籍仍显示，数值排序时放在末尾。最近阅读使用进度接口 updateTime，旧缓存需刷新后补全。接口对有阅读进度的书籍返回 0 时长时，显示“暂无有效阅读时长”，不将其视为实际累计时长。
- **我的笔记**：同步所有笔记本；左侧按书籍、公众号列出笔记来源，右侧按章节或文章分组展示该来源的划线和想法。支持来源搜索、笔记内容搜索与类型筛选。

两个 Tab 分别同步进度与笔记，互不依赖另一个功能的明细接口。首次打开 Tab 自动同步，可用「刷新当前页」再次同步。每完成一个来源即保存缓存，失败来源保留旧数据并提示。缓存可离线浏览。

## 编译和测试

```sh
./scripts/build-app.sh
open build/BookCard.app
./scripts/test.sh
```

无需完整 Xcode，Command Line Tools 即可编译。也可用 Xcode 打开 Package.swift。构建脚本生成本机临时签名的应用，未做公证或发布签名；重新编译后钥匙串可能要求重新授权。

## 数据和隐私

- Key 仅保存到 macOS 钥匙串（服务 `local.BookCard.WeRead`），不进入缓存、日志或仓库。
- 原生 URLSession 直接访问官方 HTTPS 网关，禁用重定向，不经开发者服务器。
- 请求使用平铺参数和 `skill_version: 1.0.4`；遇到升级提示或不兼容响应，保留缓存并显示错误。
- 本地 JSON 保存于 `~/Library/Application Support/BookCard/`，文件权限 0600、目录权限 0700；这些文件未额外加密，可能进入系统备份。
- 每个 Key 使用独立缓存。不假设更换 Key 就是同一个账号。
- 移除 Key 保留离线阅读；清除本地数据会删除该应用所有 Key 对应的缓存。两项操作都不修改微信读书服务端数据。
- 同步完成并通过数量、身份和分页校验后原子写入。发现旧笔记缺失时保留旧缓存并提示；旧来源也保留，直至用户主动清除本地数据。

## MVP 范围

- 列表合并书架 `books` 和所有分页的笔记本；不声称这是所有历史阅读记录。
- 暂不展示有声书、文章收藏入口、周期阅读统计或卡片。
- 公众号按原项目规则提取文章 ID 分组；划线和想法共用接口提供的文章标题。标题缺失时通过独立、无 Key 的网络会话读取公众号公开页面的 og:title，并缓存标题。公开页面不可访问时保留笔记，显示“文章（标题暂缺）”。旧版缓存缺少文章 ID，刷新后补全。
- 普通书签只在上游统计中存在，不当作划线显示；不承诺非书籍想法覆盖。
- 首次打开「我的笔记」遍历全部笔记本及其分页内容，每本书展示自己的同步时间；「我读过的书」独立遍历阅读进度。
- 接口只读；网络失败、Key 无效时已缓存数据可继续浏览。

## 验证边界

自动化测试覆盖网关错误、结构校验、Key 缓存隔离和离线数据往返。真实账号的连通性、Key 生命周期及服务端数据形态，需要在应用中用自己的 Key 实测。未使用或读取用户其他集成中的凭证。
